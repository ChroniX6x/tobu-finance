# Account-Activity lesen (E06)

`GET /api/accounts/:accountId/activity` liefert Shared `ActivityPageSchema`. Aktiver JWT-User und aktuelles verknüpftes Kontomitglied/Owner erforderlich; globales Adminrecht allein genügt nicht. Fremde/unbekannte Konten einheitlich404. Overview verwendet denselben Reader mit20Einträgen (`id/date/user/text`). Neue Desktop-/Mobile-Ansicht `/accounts/:accountId/activity`, erreichbar über „Alle Aktivitäten“.

Filter: `code` einschließlich `legacy.unknown`, `actorKind`, `subjectKind`, `subjectId`, `from` inklusive/`to` exklusive als UTC-Instant mit maximal Millisekundenpräzision. `limit` default20/max100. Unbekannte Parameter/ungültige Zeitfenster →422. Filter auf sicherer Projektion, damit fehlerhafte versionierte Rohdaten nicht als bekannter Code/Actor erscheinen.

Keyset `date DESC, _id DESC`, bestehender Index `accountId_1_date_-1__id_-1`. Zwei disjunkte geordnete Indexbereiche: restliche IDs am gleichen Zeitpunkt, danach ältere Zeitpunkte. Kein skip/Offset oder residualer OR-Scan ab Anfang. Cursor max512Zeichen, zweckgetrenntes HMAC-SHA256 aus vorhandenem privaten Signierschlüssel; bindet Konto, verifizierten User, normalisierte Filter/Limit. Kein roher User im Cursor. Manipulation/Kontextwechsel →422; Schlüsselwechsel invalidiert Cursor. Neuaufruf/Reset lädt wieder ab Anfang. Ein späterer Commit eines früher gestarteten Commands kann auch einen älteren Zeitpunkt tragen; eine feste Position nachträglich eingefügter Events wird nicht versprochen. Kein dauerhafter Snapshot über mehrere HTTP-Requests.

Pro Request ein Mongo-Read-Snapshot für Berechtigung/Mitglieder/Events/Referenzen. Keine Domain-/Event-/Revisionswrites oder Ensure. Rohereignisbudget100–500: selektive Filter können leere Seiten mit Cursor liefern. Cursor zeigt auf letzte geprüfte Zeile, nicht nur letzten Treffer; UI erlaubt Weiterblättern.

**Zusätzlicher Kostenpfad:** Nicht mehr vorhandene Referenzen benötigen eigene validierte Creation-Receipts. Diese accountgebundene Provenanceabfrage kann die gesamte eigene Historie lesen und fällt nicht unter das Rohereignisbudget. Kein neuer Index/Migration in E06. Der10k-Nachweis misst gesamte HTTP-Dauer einschließlich Provenance und enthält deren Explain. Für deutlich größere Daten erneut messen und nötigenfalls additive Indexmigration separat prüfen.

Actorlabels nur aus eigenen Mitgliedern, fehlende Zuordnung neutraler Benutzer, Legacy Unknown; kein Zahler-Actor-Mapping, keine globale User-/Emailabfrage. Namen max120UTF16-Einheiten ohne zerteilte Codepoints, Objektlabels statisch/minimiert. Alle Referenzen inklusive Params/Deltas geprüft. Fremde und fehlende Objekte ohne eigenen Creation-Receipt identisch redigiert: bekannte Aktion/Actor bleiben, `params:null`, `subject:null`, `detailsUnavailable:true`. Keine globale Existenzoracle. Belegte gelöschte eigene Subjects historisch lesbar ohne Link. Live-Links führen ausdrücklich zu weiteren Aktivitäten desselben Objekts im eigenen Konto. Unlesbare IDs/Instants →503, keine stille Auslassung/GET-Reparatur.

Mongo-Adapter prüft geladene Events und historische Belege zusätzlich auf echte BSON-ObjectIds und gültiges BSON-Date. Die tolerante Stringunterstützung des portablen Contract-Decoders gilt nicht für Indexvergleiche. Falsche BSON-Typen →503 ohne Reparatur oder Belegfreigabe. Dies ist kein vollständiger Datenbankschema-Audit pro Request: gültige BSON-Typen sind bereits verbindliche Baseline-/E03-/E05-Voraussetzung; außerhalb des gelesenen Fensters liegende Typdrift wird durch den Reader nicht umfassend inventarisiert.

Gruppen nur aus validiertem schemaVersion1 mit trusted batch/correlation und gleichem Konto/Actor/Trigger/Initiator. Gemischte Codes eines Commands zusammengehörig. Server liefert opaken Gruppenschlüssel mit `scope:loaded_only`; keine Gesamtzahl oder Abschluss-/Erfolgsbehauptung. UI dedupliziert EventIDs und gruppiert sämtliche geladenen Seiten mit tatsächlich geladenem Count und Hinweis auf unbekannte ungeladene/fehlgeschlagene Teile. Neue Recurrence-Primitiven und spätere Domain-PartialSuccess-Nachweise bleiben nachfolgenden Schritten vorbehalten.

Native beschriftete Controls/Details, sichtbarer Tastaturfokus, Live-Status/Fokus nach Nachladen, Angular-escaped Text. Account-/Filterwechsel leert Daten und bricht alte Requests ab. Ungültige URL blockiert Nachladen bis Reset/Korrektur. Zugriffsverlust leert Daten; Seitenfehler erhält geladene Seiten und wiederholt denselben Cursor. Cursor werden nicht in URL-Filtern gespeichert.

Bei422 Filter/Cursor zurücksetzen; bei503 Rohereignisse ausschließlich read-only diagnostizieren, nicht automatisch ändern. Keine Migration/Ensure erforderlich. Tests und tatsächliche Belege: [E06-Bericht](../agents/runs/E06.md).
